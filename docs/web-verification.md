## בדיקה בדפדפן

- התחברות באמצעות טופס username/password, עם סיסמה שנקראה מקובץ פרטי מקומי והוזנה בטופס בלבד.
  פלט שעלול לכלול את הסיסמה נשמר זמנית בקובץ פרטי ולא הוצג; קובצי העזר נמחקו אחרי הבדיקה.
- יצירת בקשת חשבונית מס־קבלה: `DEMO-BROWSER-INVOICE-001`, שני פריטים במחיר יחידה 12.35.
  הוצגו UUID, גרסה, סכום הדגמה 24.70 והתוצאה ״לא נוצרו רשומות ב־Priority״.
- חזרה בדפדפן ושליחה נוספת החזירו אותו UUID והודעת מניעת כפילות.
- בקשת ספק: `DEMO-BROWSER-SUPPLIER-001`, עם שם בדוי, `000000000` ודוא״ל בדומיין example.test.
- בקשת ספק חדש והזמנת רכש משולבת: `DEMO-BROWSER-PO-001`, באמצעות טופס הדפדפן בתצוגת 390×844.
- חיפוש לפי אסמכתה החזיר בקשה אחת; פתיחתה החזירה את אותו מזהה ואת התוצאה השמורה.
- יציאה ביטלה את הגישה; ניווט ישיר לתוצאה הפנה לטופס התחברות.
- בוצעה בדיקה חזותית למסכי הכניסה, הדשבורד והתוצאה בנייד; לא נמצאה גלישה רוחבית של מסך הנייד.

הבדיקה מול המסד המקומי לאחר תהליך הדפדפן הראתה **3 בקשות, 0 execution attempts ו־0 created records**.
אלה בקשות הדגמה באתר בלבד. הן נשארו זמינות למשתמש לצורך התרשמות.

## תיקונים שעלו במהלך האימות

- `Referrer-Policy: no-referrer` גרם ל־Origin:null בשליחת טופס ב־Chromium. הוחלף ל־same-origin,
  תוך שמירת אימות Origin מדויק ו־CSRF.
- בקשת favicon חסרה הופנתה להתחברות ושינתה את cookie ה־CSRF של טופס פתוח. favicon מחזיר עכשיו 204,
  ונתיבים ציבוריים לא מוכרים מחזירים 404 בלי שינוי cookie.
- החלפת סיסמה או חסימת חשבון בזמן אימות סיסמה אסינכרוני כבר אינן מאפשרות הנפקת session חדש.
- session נבדק שוב לאחר קריאת גוף הטופס, כדי לאכוף יציאה/תפוגה/החלפת סיסמה שהתרחשו במהלך הקריאה.
- כל מפתח ניסיון חוזר נשמר ומקושר לבקשה המקורית, גם כשהכפילות זוהתה לפי האסמכתה.
- setup אקראי משתמש ביצירה בלבד ואינו דורס חשבון שנוצר במקביל. נוספו בדיקות migration ו־rollback.
